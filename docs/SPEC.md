## 1. 프로젝트 개요

### 1.1 목적
장애인(특히 **시각장애** 및 **지체장애/휠체어 이용자**)이 독립적으로 사용할 수 있는 접근성 중심 키오스크 UI를 개발한다. 1차 목표는 **동작하는 Fake Demo** — 실제 결제·음성인식 하드웨어 없이 전체 주문 흐름을 시연 가능한 수준으로 구현한다.

### 1.2 범위
| 구분 | 포함 (Fake Demo) | 제외 (향후 확장) |
|------|-----------------|----------------|
| UI | PyQt6 기반 키오스크 화면 | 실제 키오스크 OS 통합 |
| 주문 | Claude API 자연어 주문 처리 | 실시간 STT(음성→텍스트) 엔진 |
| 결제 | 가짜 결제 시뮬레이션 | 실제 PG/카드 단말 연동 |
| 음성 | TTS 안내 출력 | 마이크 기반 음성 주문 |

### 1.3 핵심 결정 사항
- **기술 스택**: Python 3.11+ / **PyQt6**
- **접근성 초점**: 시각장애, 지체장애(휠체어)
- **LLM**: Claude API 실제 연동 (`claude-opus-4-8`), Mock 토글 지원
- **데모 업종**: **버거킹** (대표 메뉴를 적당히 구성, `data/menu.json`)
- **TTS**: **오프라인** (`pyttsx3`), 간단 버전
- **화면**: **세로형(포트레이트)** 540×960 (9:16) 기준
- **입력**: 현재 단계는 **마우스/키보드** (터치는 향후)

## 2. 사용자 및 접근성 요구사항

### 2.1 대상 사용자 페르소나
1. **시각장애 사용자 (전맹/저시력)**
   - 화면을 보지 못하거나 부분적으로만 인식
   - 음성 안내(TTS)와 음성/대화형 주문에 의존
2. **지체장애 사용자 (휠체어 이용)**
   - 화면 상단에 손이 닿지 않음
   - 정밀한 터치가 어려움 → 큰 터치 영역 필요

### 2.2 접근성 요구사항 (WCAG 2.1 AA + 키오스크 추가 기준)

#### 시각장애 대응
- **TTS 음성 안내**: 모든 화면 진입·포커스 이동·상태 변화 시 음성 출력
- **고대비 모드**: 명도 대비 ≥ 7:1 (AAA 수준 권장)
- **동적 글자 크기**: 기본 24pt, 최대 200%까지 확대
- **대화형 주문 우선**: "아메리카노 한 잔 주세요" 식 자연어 주문으로 시각 탐색 없이 완료 가능
- **포커스 가시화**: 키보드/물리 버튼 탐색 시 명확한 포커스 표시 + 음성 읽기

#### 지체장애(휠체어) 대응
- **저위치 UI 모드**: 핵심 조작 영역을 화면 하단 1/3에 배치하는 토글
- **큰 터치 타깃**: 최소 60×60 px (권장 88×88 px), 충분한 간격
- **음성 주문으로 터치 최소화**: 손 사용을 줄이는 대안 경로 제공
- **타임아웃 연장**: 입력 대기 시간을 길게(기본 90초) + 연장 옵션

#### 공통
- 모든 기능은 **음성만으로도**, **터치만으로도** 완료 가능해야 함 (이중 경로)
- 단순하고 일관된 화면 흐름, 한 화면당 결정 수 최소화

## 3. 기능 명세

### 3.1 화면 흐름
```
[시작/접근성 설정] → [메뉴 탐색 or 대화형 주문] → [장바구니 확인] → [결제(Fake)] → [완료/영수증]
```

### 3.2 화면별 기능

#### F-1. 시작 화면 / 접근성 설정
- 진입 시 TTS: "환영합니다. 주문을 시작하려면 화면을 누르거나 말씀해 주세요."
- 접근성 빠른 설정: 고대비 ON/OFF, 글자 크기, 저위치 모드, 음성 안내 ON/OFF
- 큰 시작 버튼 1개 + "도움이 필요하세요?" 음성 안내

#### F-2. 메뉴 탐색 (터치 경로)
- 카테고리 → 메뉴 항목 (그리드, 큰 카드)
- 각 메뉴: 이름 / 가격 / 이미지 / 음성 읽기 버튼
- 포커스 이동 시 항목 정보 TTS 자동 안내

#### F-3. 대화형 주문 (LLM 경로) ⭐
- 텍스트 입력창 + (데모) "말하기" 버튼 → 텍스트 입력으로 시뮬레이션
- Claude API가 자연어를 해석 → 주문 항목/수량/옵션 추출 → 장바구니 반영
- Claude 응답을 TTS로 출력 (예: "아메리카노 1잔 담았습니다. 더 필요하신가요?")
- 모호하면 되묻기 (예: "따뜻한 걸로 드릴까요, 차가운 걸로 드릴까요?")

#### F-4. 장바구니
- 담긴 항목 목록, 수량 변경/삭제 (터치 + 음성)
- 총액 표시 + TTS 안내
- "결제하기" 버튼

#### F-5. 결제 (Fake)
- 결제 수단 선택 화면 (카드/모바일 — 시각적 표시만)
- "결제 중..." 애니메이션 → 2초 후 가짜 승인
- 실패 시나리오 토글 (데모용)

#### F-6. 완료 / 영수증
- 주문 번호 표시 + TTS 안내
- "주문이 완료되었습니다. 주문번호는 42번입니다."
- 일정 시간 후 시작 화면으로 자동 복귀

### 3.3 LLM 주문 처리 상세

**입력**: 사용자 자연어 발화(텍스트) + 현재 메뉴 카탈로그 + 현재 장바구니 상태

**처리**: Claude API에 다음을 전달
- System 프롬프트: 키오스크 주문 도우미 역할, 메뉴 범위 내에서만 응답, 친절하고 짧게
- Tool use 또는 Structured Output으로 주문 액션 추출:
  ```json
  {
    "action": "add_item | remove_item | update_qty | confirm | clarify | answer",
    "items": [{"menu_id": "americano", "qty": 1, "options": {"temp": "hot"}}],
    "speech": "아메리카노 따뜻한 거 한 잔 담았어요. 더 주문하시겠어요?"
  }
  ```
- `output_config.format` (Structured Output)로 스키마 강제

**출력**: 장바구니 상태 갱신 + `speech` 필드를 TTS로 재생

**모델 설정**
- 모델: `claude-opus-4-8`
- `thinking`: `{"type": "adaptive"}` (필요 시), `output_config.effort: "low"` (지연 최소화)
- 스트리밍 사용으로 응답 지연 체감 감소

- `PyQt6` — UI
- `anthropic` — Claude API SDK

- `python-dotenv` — 환경변수
- (확장) `SpeechRecognition` / `vosk` — 실제 STT

### 4.4 환경설정
- `ANTHROPIC_API_KEY` — 환경변수로 주입, 코드에 하드코딩 금지
- `KIOSK_LLM_MODE` = `claude` | `mock` — 개발은 Mock, 시연은 실제
